TODO. 大文件的"读"本身并不适合多线程并发(IO争抢), 解析和存储"通常才是性能关键
不拆分文件:
  - 同步读取数据, 并发处理和持久化    => 最佳实践
  - 偏移并发读取, 并发操作各个部分数据 => 必须预先建立索引划分(耗时)
拆分文件:
  - 单机多线程并发每个Split文件  => 预先切割分片(增加IO扫描)
  - 多机分布式处理每个Split文件  => 对切分文件进行分发

TODO. 如何拆分文件 ?
判断是否拆分以及拆分数量(避免出现空文件，或拆分后文件数量不足)
当每个Item数据格式统一且大小标准时: 按文件大小均分最佳 => 只扫描一遍文件(10GB, 45S)
当每个Item数据格式统一但大小随机时: 按平均数均分最佳, 均衡并发存储和解析 => 扫描两遍文件(10GB, 85S)
