大文件本身并不适合多线程并发读取(IO争抢), Read操作通常不是性能关键, 解析和存储才是
Spring Batch并未提供直接并发读取大文件Reader API
  - 自定义实现Reader并发模型, RandomAccessFileReader等
  - 考虑local chunking或partitioning

不拆分文件:
  - 同步读取数据, 并发处理和持久化    => 最佳实践
  - 偏移并发读取, 并发操作各个部分数据 => 必须预先建立索引(耗时)
拆分文件:
  - 单机多线程并发每个Split文件  => 预先切割分片(增加IO扫描)
  - 多机分布式处理每个Split文件  => 对切分文件进行分发
